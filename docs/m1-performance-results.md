# M1/T1 performance evidence

Measured with Node.js, CPU details omitted, platform details omitted. Two M1 states are recorded:
the first port at `c7166ed`, and the builtin-era port at `1bb2d11` after
`text_slice`, `text_find`, `text_split`, `map_copy`, `list_copy`,
`list_to_text`, `number_to_text`, and `json_to_text`. Both compilers emitted
identical bytes for every measured workload and application.

Raw evidence:

- Builtin-era [runtime](m1-builtins-runtime-baseline.json) and
  [self-build](m1-builtins-self-build.json).
- Pre-builtin [runtime](m1-runtime-baseline.json),
  [self-build](m1-self-build.json), and
  [application](m1-application-baseline.json).

## Builtin-era result

M1 source grew to 48,806 bytes and generated T1 to 53,201 bytes, but the hot
lexer/parser helpers were replaced by host operations:

- `text_slice` replaced per-character token spelling.
- `text_find` replaced character-membership loops.
- `text_split` replaced manual line scanning.
- `map_copy` replaced scope copying.
- `list_to_text` replaced the join helper.
- `number_to_text` replaced decimal formatting.
- `json_to_text` replaced JSON string quoting; token field order remains explicit.

### Verification

- `mini test`: 322/322 active scenarios passed; four proposals remain pending.
- `./bin/mini test --candidate .cache/compiler.mini.ts`: 259/259 Mini-source
  scenarios passed.
- A local differential pass compiled all 222 `.mini` files under `cases/`,
  `samples/`, and `compiler/` with T0 and T1: all 222 compile results and all
  222 token streams matched.
- `application-performance.ts --check .cache/compiler.mini.ts`: 69/69
  application/fixture combinations passed.

### Compiler probes

Fresh-process compile medians, T0 to T1:

- 1,000 statements: 72.2 to 66.4 ms (0.92x).
- 4,000 statements: 72.4 to 78.8 ms (1.09x).
- 16,000 statements: 89.4 to 130.5 ms (1.46x).
- 10,000-character text literal: 65.1 to 59.8 ms (0.92x).
- 40,000-character text literal: 62.7 to 62.8 ms (1.00x).
- 160,000-character text literal: 63.3 to 71.5 ms (1.13x).
- 100-term addition expression: 62.3 to 60.2 ms (0.97x).
- 1,000/4,000-term expression stress: 1.10x/1.09x, with the same `.ts` stack
  failures under both compilers and identical emitted text.

Execution medians were 0.95–1.10x. The generated workload hash is identical.

### Self-build

`compiler/compiler.mini` is 48,806 bytes. In a 21-sample alternating A/B run:

- Wall time: 77.2 to 75.4 ms (0.976x).
- User CPU: 0.10 to 0.12 s (1.20x).
- Maximum RSS: 90.7 to 92.8 MiB (1.023x).
- Peak footprint: 47.6 to 50.3 MiB (1.057x).
- Output: byte-identical.

The generation chain was stable and identical:

- Generation 1: 93.4 ms, 90.6 MiB RSS, 47.5 MiB footprint.
- Generation 2: 87.7 ms, 93.0 MiB RSS, 50.5 MiB footprint.
- Generation 3: 84.9 ms, 94.0 MiB RSS, 51.6 MiB footprint.

On the 304,071-byte, 16,000-assignment source, T1 took 134.8 ms versus 94.3 ms
(1.43x), with user CPU 1.54x. Peak RSS and footprint were lower for T1 on this
input (0.93x and 0.91x).

### Improvement over the first port

- 16,000 statements: 1.72x to 1.46x.
- 4,000 statements: 1.31x to 1.09x.
- 1,000 statements: 1.07x to 0.92x.
- 160,000-character text: 1.18x to 1.13x.
- 40,000-character text: 1.20x to 1.00x.
- Self-build wall: +7.5% to −2.4%.
- Self-build RSS: +5% to +2.3%.
- Self-build peak footprint: +11.5% to +5.7%.
- Self-build user CPU: +30% to +20%.
- 304 KB source compile: 1.62x to 1.43x.

The builtins did not erase the large-source gap, but they reduced it materially
without changing generated bytes.

### Profile

A CPU profile of the 16,000-statement compile now shows T1 self-time mainly in
`tokenize`, `$mini_map_set`, `parser_statement`, `parser_comparison`,
`lex_advance`, `new_token`, `parser_new`, and `parser_program`; `$mini_text_find`
is small. The former `is_letter`/character-membership loop no longer appears in
the top entries.

## Pre-builtin baseline

The first M1 at `c7166ed` recorded these values before the builtin set:

- 1,000/4,000/16,000 statements: 1.07x/1.31x/1.72x.
- 10,000/40,000/160,000-character text: 1.08x/1.20x/1.18x.
- Self-build: 74.3 to 79.8 ms (1.075x), RSS 1.05x, footprint 1.115x, user 1.30x.
- 304 KB source: 91.1 to 147.6 ms (1.62x), RSS 0.95x, footprint 0.93x.
- Generated workload medians stayed within ordinary noise; generated bytes were
  identical.

The [paired application suite](application-performance.md) full run was recorded
before the builtin set; its 690 measured calls and 46 semantic checks passed, and
all ten generated applications were byte-identical between T0 and T1. The
builtin-era change was rechecked with the 69-combination `--check` run.

## Promotion status

T1 is the active compiler at `dist/compile.ts`, selected by
`config/compiler.json` and pinned by `config/bootstrap.json`. T0 remains the
reference compiler and tooling analyzer.

Large synthetic sources still compile about 1.43x slower than T0. That gap is a
tracked performance follow-up, not a correctness blocker. Further gains should
target token/expression map allocation and repeated parser state lookups; the
text-helper and collection-copy gaps are now much smaller. Preserve the fixed
point and rerun this audit for any further optimization.
