# Bootstrap

The self-hosted bootstrap is the only compiler implementation and is selected by
[config/compiler.json](../config/compiler.json).
[config/bootstrap.json](../config/bootstrap.json) pins the generated
`dist/compile.js` to `tools/compiler.mini`. The former handwritten
implementation was removed after promotion and fixed-point verification.

`bin/bootstrap` is the tracked seed. It is generated from
[tools/bootstrap.mini](../tools/bootstrap.mini), embeds the compiler and the
bootstrap driver, and is the only tracked executable under `bin/`. Running it
rebuilds `dist/compile.js`, verifies the compiler fixed point, compiles
`dist/build.js`, and generates every other tool and launcher.

```text
./bin/bootstrap
./bin/mini verify
```

For a full clean rebuild, run `./bin/bootstrap --clean`. It runs `git clean
-ffdx` from the project root, removing every untracked and ignored item in the
checkout, including dependency installs, generated tools, caches, prior local
packages, and previews. Tracked source files and tracked edits are preserved.
It then reinstalls locked dependencies, rebuilds the compiler and tools, runs
repository, case, unit, LSP, release, and editor checks, and packages the VS
Code extension to `dist/rebuild/mini-GROUP-vVERSION.vsix`.

`dist/` and generated `bin/` entries are ignored by Git. CI bootstraps before
running checks and publishes built tools and release artifacts.

Tool behavior is implemented in mini. The dispatcher, verifier, release harness,
formatter, language server, test runner, benchmark tool, and CI task runner are
generated from `tools/*.mini`. The test runner uses a small Node TypeScript
worker pool to launch independent Mini-selected jobs concurrently; fixture
selection, execution checks, and reporting remain in Mini. Other host TypeScript
supports editor clients, performance measurement, and host-specific integration
tests.

The mini compiler source lives in
[tools/compiler.mini](../tools/compiler.mini); the compiler generated from it is
promoted as `dist/compile.js`. The fixed point is that compiling the compiler's
own source produces it byte for byte. `config/bootstrap.json` records the
source, compiler,
and example identities. The [port history](port-history.md)
records the first port's continuity with the retired handwritten design.

Delivery uses compilation, not a runner:

```text
mini compile tools/compiler.mini
node compiler.mini.js compile tools/compiler.mini
```

Both write `compiler.mini.js` by default. An optional final argument selects another
output path. `mini-compile` and `minic` are aliases for `mini compile`.
The generated compiler implements the same `compile SOURCE.mini [OUTPUT.js]`
interface and writes self-contained JavaScript. Node common functions are available;
handwritten compiler helpers must not be required.

Primitive host I/O is expressed through [common functions](functions.md). These implementations
must not contain mini parsing or compilation logic. Any library code used by
the compiler must be included in its source/build and generated bootstrap;
it must not introduce another prerequisite tool or package.

Promotion is complete: the bootstrap version is assigned, the generated entry is
selected in `config/compiler.json`, and `config/bootstrap.json` records:

```json
{
  "compiler": "dist/compile.js",
  "source": "tools/compiler.mini",
  "example": "cases/language/005-002-io-sample.case.json"
}
```

The echo example is an example-kind manifest reusing the runnable I/O sample. It
uses the [case format](cases.md): source and input/output streams remain separate
files.

The verifier copies the shipped compiler and mini source into an isolated
directory, invokes `node PREVIOUS.js compile tools/compiler.mini NEXT.js` three times,
and requires each output file to equal the shipped compiler byte for byte.
It uses the last generation to compile and run every example scenario,
checking stdout, stderr, and exit status. Release metadata records source,
compiler, generation, example, and stream identities.

The [compiler performance evidence](compiler-performance-results.md) records
the generated compiler
against the former handwritten reference on the compiler source, representative large
inputs, and self-builds. The generated compiler is active and the handwritten
one is retired. The large-source compile
gap remains a measured follow-up, not a correctness blocker. The fixed-point
verifier does not perform performance acceptance; equal generated bytes alone do
not establish acceptable speed or memory use.

After replacement, compiler behavior lives in mini. Regenerate the bootstrap;
never hand-edit it. Implement new syntax using old syntax first, then follow
the [language evolution guide](evolving-language.md) to migrate source and
promote a verified pair. Record the prior builder tag/commit in release notes.

## Syntax migration

Keep enough language expressiveness for a readable, maintainable compiler.
Choose changes by their total implementation and migration cost, not by
construct count alone. Avoid both compiler contortions and elaborate language
machinery.

The [user guide](evolving-language.md) shows both a breaking S1-to-S2 bridge
and a route that temporarily accepts both forms. A breaking bridge need not
self-compile its old source; it must stay temporary until the final source and
generated compiler reach the fixed point together. Treat that complete
transition as one atomic migration. Compatible support/adoption steps can be
separate self-hosted commits.

Tool cases invoke real commands. Self-hosting verification uses the promoted
generated bootstrap.
